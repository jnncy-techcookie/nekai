# NEKAI documentation

| File | What it is |
|---|---|
| `technical-documentation.docx` | The technical documentation as an editable **Word** file (guidelines, Section 9). Generated by `build-docx.js` |
| `technical-documentation.pdf` | The same document as a PDF. Generated from `src/technical-documentation.html` |
| `architecture.png` | The architecture diagram. Generated from `src/architecture.svg` |
| `src/` | The sources for the PDF and the diagram |
| `screenshots/` | Screenshots that both builds pick up automatically (see below) |
| `build.js` | Rebuilds the PDF and the PNG |
| `build-docx.js` | Rebuilds the Word file |

## Which file do I edit?

- **To finish the document by hand** (fill in roles, paste screenshots, tweak wording): open the `.docx` in Word, edit it, and export a PDF from Word (*File → Save As → PDF*). That PDF is what you submit.
- **To regenerate from the repository**: run the builds below. The Word file and the PDF carry the same text from two sources (`build-docx.js` and `src/technical-documentation.html`), so a wording change has to be made in both. A rebuild **overwrites** the generated files, including any edits made by hand in the `.docx`.

## Rebuild

```bash
node docs/build.js                          # PDF + architecture.png: needs Node and Chrome or Edge, no npm packages
cd docs && npm install && node build-docx.js   # Word file: needs Node and the docx package
```

Set `CHROME_BIN` if Chrome or Edge isn't found automatically.

## Screenshots to add

Both documents show a yellow **INSERT SCREENSHOT** box wherever a file is missing from `docs/screenshots/`. Either save each screenshot there with exactly this name and rebuild (the PNG is then placed automatically), or, in Word, click the box and paste the screenshot over it:

| File | What to capture |
|---|---|
| `github-webhook.png` | GitHub, repository *Settings → Webhooks*: the ngrok webhook with a recent delivery showing a green tick |
| `jenkins-stage-view.png` | Jenkins, job `nekai`, Stage View after a successful build: all five stages green |
| `jenkins-failed-test.png` | Stage View of a build that failed at *Test* (later stages not run), ideally next to the app still showing the previous build label |
| `rollback-job.png` | Jenkins, job `nekai-rollback`: *Build with Parameters* with `ROLLBACK_TAG` filled in, and the finished build |
| `rollback-result.png` | The app in the browser after the rollback, with the earlier build number in the corner |
| `persistence-proof.png` | The library before and after a redeploy (or `docker compose down` then `up -d`), plus `docker volume ls` showing `nekai_pg-data` |

Screenshots must be PNG files for the automatic placement in the Word build.

## Fill-ins marked in yellow

Both documents mark what only the group can supply: course and section, group name, each member's role, middle initials, and one surname. In Word, search for yellow highlighting (*Find → Format → Highlight*). In the PDF source, search `src/technical-documentation.html` for `class="todo"`.
